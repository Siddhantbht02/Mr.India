\begin{abstract}
This paper improves generative steganography using a diffusion model. Instead of modifying an existing photograph, the proposed system creates a new image from noise that carries a hidden message. Existing diffusion-based approaches can suffer from recovery drift, unusual noise patterns, and bit errors caused by rounding or transmission changes. We address these problems with three connected improvements. First, a repeated correction process improves the recovery of the hidden noise when the image-generation process is reversed. Second, a distribution-preserving encoder makes the message-bearing values resemble the natural noise expected by the diffusion model. Third, an error-correction layer and a self-describing header repair damaged bits and tell the receiver how to decode and verify the message automatically. Across 20 automated trials, the improved system recovered every message without a bit error. The generated images also achieved high visual quality, while the tested hidden values showed no significant departure from the expected noise distribution.
\end{abstract}

\section{Introduction}
Steganography is the science of hiding secret data inside everyday media so that an observer does not even realize a secret message exists. For decades, most steganographic methods have relied on \textit{carrier modification}: taking an existing photo and tweaking pixel values or frequency coefficients to embed bits (e.g., S-UNIWARD~\cite{holub2014universal}, WOW~\cite{holub2012designing}). However, modern steganalysis tools and deep convolutional networks (such as SRNet~\cite{boroumand2018deep}) are trained specifically to detect these tiny modifications, making traditional steganography increasingly easy to spot.

To overcome this fundamental limitation, researchers have turned to \textbf{generative steganography}. Instead of modifying an existing image, a generative model (such as a diffusion model) synthesizes an entirely new, realistic image directly from the secret message. Because there is no original ``cover'' image to compare against, there are no modification artifacts to detect.

\subsection{The Three Core Challenges}
While the idea is promising, creating a reliable generative diffusion steganography system in practice encounters three difficult obstacles:
\begin{enumerate}
    \item \textbf{Recovery Drift:} Diffusion models generate images through many small steps. Reading the message requires reversing those steps. In standard DDIM inversion~\cite{song2020denoising}, small approximation and rounding errors can accumulate, flip hidden bits, and corrupt the recovered message.
    \item \textbf{Statistical Detectability:} Ordinary diffusion noise has a smooth bell-shaped pattern. If message bits are inserted too directly, they create unnatural spikes or clusters. Statistical tests may flag these patterns as suspicious.
    \item \textbf{Fragility to Channel Noise (The Engineering Problem):} In real communication, images encounter minor color rounding, floating-point differences across hardware, or lossy channel noise. Most existing research prototypes hard-code message sizes and have zero error recovery: flipping even a single bit causes total extraction failure.
\end{enumerate}

\subsection{Our Solution}
This work builds on the diffusion-based generative steganography scheme of Zhou \textit{et al.}~\cite{zhou2025improved}, which hides bits by replacing the DCT coefficients of a Gaussian latent with fixed $\pm 1.0$ values and recovers them through DDIM inversion. Their conclusion names the realism of the generated stego images, that is, reducing their visual and statistical differences from real images, as the main direction for future work. We take the statistical part of this future scope as the item we implement: making the message-bearing latent behave like ordinary Gaussian noise and checking this with formal normality tests. Because the extraction accuracy reported in~\cite{zhou2025improved} stays below 100\% on some datasets at 50 sampling steps (99.91\% on Cifar10 and 99.93\% on Bedroom), statistically shaped values can only be decoded reliably if the noise is recovered exactly. Our fixed-point inversion and error-correction layer serve this purpose. Robustness to attacks such as JPEG compression, which~\cite{zhou2025improved} also lists as future work, is not claimed here (see the Discussion).

In this work, we present a complete, robust system that directly solves all three issues (Fig.~\ref{fig:easy_system_pipeline}):
\begin{itemize}
    \item \textbf{Repeated Recovery Correction:} At every recovery step, the system checks its estimate and improves it several times. This greatly reduces accumulated errors and produced a 0.000000\% bit error rate in our trials.
    \item \textbf{Natural-Looking Noise Encoding:} The message bits are randomized and spread smoothly through the same bell-shaped range used by ordinary diffusion noise. This avoids obvious patterns that statistical detectors could identify.
    \item \textbf{Automatic Error Correction:} The system supports several protection levels, spreads nearby errors apart, and adds a 45-byte header. The receiver can discover the message length, protection level, and integrity information automatically.
\end{itemize}

\section{Practical Context and Intended Use}

\subsection{Why Generate a New Image?}
Traditional steganography starts with an existing image and changes a small number of pixels. The changes may be invisible to a person, but a computer can compare local patterns and discover that the image has been edited. Generative steganography follows a different idea. It creates the complete image from the hidden data, so there is no original photograph that contains a separate set of embedding changes.

This does not mean that every generated image is automatically secure. The hidden data must still be prepared carefully. If the input noise contains repeated or unnatural values, the generated image may inherit patterns that a detector can learn. The purpose of the noise-shaping stage is therefore not only to store bits, but also to make the model input look similar to the input used during normal image generation.

The approach is useful when the sender and receiver already share the same model and secret settings. A sender can create an ordinary-looking image, share it through a normal communication channel, and allow the receiver to recover the message later. Possible research applications include private metadata transfer, ownership information, experiment identifiers, and small verification messages attached to synthetic media.

\subsection{Simple End-to-End Example}
Consider a short message such as ``Meeting at 4.'' The system first adds information describing the message length and the selected error-protection level. It also adds integrity checks so that the receiver can determine whether the recovered message is complete. The protected bits are then shuffled and randomized to remove obvious patterns.

Next, each bit is represented by a value selected from a smooth random range. These values are shaped into natural-looking diffusion noise and passed to the image generator. The resulting image can then be transmitted or stored like an ordinary synthetic image. At the receiving side, the same model reverses the image-generation process. Repeated correction reduces recovery drift, after which the system reads the hidden values, restores the original bit order, repairs small errors, and verifies the final message.

\subsection{Operating Assumptions}
The current system assumes that the sender and receiver use compatible model versions and share the required secret seed. It also assumes that the transmitted image is not heavily resized, cropped, filtered, or recompressed. The error-correction layer can handle small disturbances, but it cannot recover information that has been completely removed. These assumptions define the intended scope of the experiments and help separate the tested results from broader real-world conditions.

\section{System Architecture and Key Innovations}

\subsection{Accurate Image Reversal}

\subsubsection{Why Ordinary Reversal Loses Information}
A diffusion model creates an image through many small steps. Recovering a hidden message requires running those steps in the opposite direction. Standard reversal estimates each earlier state from the information currently available. Each estimate may be only slightly wrong, but the errors can build up across dozens of steps. Eventually, the recovered noise differs enough from the original noise to change message bits, as illustrated in Fig.~\ref{fig:trajectory_comparison}.

\subsubsection{How Repeated Correction Helps}
Instead of accepting the first estimate at each step, the system improves it through a short correction loop:
\begin{enumerate}
    \item Begin with the best estimate available from the previous step.
    \item Ask the diffusion model to refine that estimate.
    \item Repeat the refinement a few times, stopping when the result no longer changes noticeably.
\end{enumerate}
In the experiments, only a few refinements were normally needed. This simple feedback process prevented small errors from growing and enabled complete message recovery in all reported trials.

\subsubsection{The Problem with Naive Bit Insertion}

Natural diffusion noise should instead form a smooth bell-shaped distribution. A statistical detector may notice the difference when the message is inserted too directly.

\subsubsection{Simple Encoding Process}
The distribution-preserving encoder converts message bits into natural-looking noise in three straightforward steps (Fig.~\ref{fig:dpac_intuitive}):
\begin{enumerate}
    \item \textbf{Randomize the Bit Pattern:} The message is mixed with a shared pseudo-random sequence. This removes repeated words, headers, and other predictable patterns.
    \item \textbf{Choose a Random Value:} A zero uses the lower half of a range, while a one uses the upper half. The exact position inside that half is chosen randomly, so the output remains smooth rather than forming visible spikes.
    \item \textbf{Shape the Values Like Natural Noise:} The smooth values are converted into the same bell-shaped pattern expected by the diffusion model. This makes message-bearing noise resemble ordinary generation noise.
\end{enumerate}

During extraction, the receiver reverses the conversion and checks whether each recovered value belongs to the lower or upper half of the range. It then removes the shared random mask to restore the original message bits.

\subsubsection{Autonomous Self-Describing Framing}
Rather than requiring the sender and receiver to pre-agree on message length or coding settings, every message is automatically prefixed with a 45-byte self-describing header (Fig.~\ref{fig:framing_intuitive}):
\begin{itemize}
    \item \textbf{MAGIC (4 Bytes):} Identifies the steganographic payload (`b"STEG"`).
    \item \textbf{RATE\_ID (1 Byte):} Specifies the error correction rate used ($R \in \{1/2, 2/3, 3/4, 5/6\}$).
    \item \textbf{PAYLOAD\_LEN (4 Bytes):} Tells the receiver exactly how many secret bytes follow.
    \item \textbf{CRC32 (4 Bytes) \& SHA-256 (32 Bytes):} Dual checksums that verify complete data integrity.
\end{itemize}
The header is always protected at the highest error-correction level (Rate 1/2, 720 coded bits), ensuring the receiver can always read the metadata even under adverse noise.

\subsubsection{Adjustable Error Protection}
The payload is protected by adding extra check bits. The sender can choose from four levels depending on channel quality:
\begin{itemize}
    \item \textbf{Maximum Protection:} Adds one check bit for every data bit. This is best for noisy channels.
    \item \textbf{High Protection:} Uses fewer check bits while keeping strong recovery ability.
    \item \textbf{Balanced Protection:} Provides a middle ground between safety and message size.
    \item \textbf{Maximum Capacity:} Uses the fewest check bits and is best for clean channels.
\end{itemize}
Before embedding, the bit order is shuffled. If a small area is damaged, the errors are spread across the message instead of remaining in one cluster, which makes them easier for the decoder to repair.

\section{Experimental Results and Verification}

\subsection{Experimental Setup}
To evaluate the system, we implemented the complete pipeline in PyTorch and ran automated benchmark suites:
\begin{itemize}
    \item \textbf{Diffusion Architecture:} Continuous Denoising Diffusion model~\cite{ho2020denoising} operating on RGB images at $64 \times 64$ resolution ($12{,}288$ total latent dimensions).
    \item \textbf{Schedule:} 50 uniform DDIM steps ($S=50$) with linear noise schedule $T=1000$.
    \item \textbf{Benchmarked Payload:} 54 message bytes (1,584 coded bits under Rate 1/2).
    \item \textbf{Evaluation Metrics:} Peak Signal-to-Noise Ratio (PSNR), Structural Similarity (SSIM)~\cite{wang2004image}, Perceptual Similarity (LPIPS)~\cite{zhang2018unreasonable}, Bit Error Rate (BER), and inference latency.
\end{itemize}
All code, result plots, and logs are available at \url{https://github.com/Siddhantbht02/Mr.India}.

\section{Discussion, Limitations, and Future Work}

\subsection{What the Results Show}
The experiments show that the three parts of the system support one another. Repeated correction improves the recovered noise, natural-looking noise encoding reduces obvious statistical patterns, and error correction protects the final message. The automatic header also makes the receiver easier to use because important settings travel with the payload instead of being entered manually.

The results should be understood within the tested setup. A zero bit error rate across 20 trials shows consistent performance in those trials, but it does not prove that every possible image or communication channel will produce the same result. Similarly, passing the reported statistical tests means that those tests did not find a clear difference in the evaluated samples. It does not guarantee that every future steganalysis method will fail.

\subsection{Current Limitations}
The present evaluation uses small $64 \times 64$ images and a controlled diffusion pipeline. Larger images may require more memory, longer processing time, and additional testing. The sender and receiver must also use compatible software, model weights, and secret settings. Even a small implementation difference can affect the recovered internal values.

Another limitation is channel modification. Social-media platforms often resize images, change color values, remove metadata, or apply lossy compression. Mild changes may be repaired by the error-correction layer, but strong changes can destroy too much hidden information. Cropping is especially difficult because it removes part of the generated carrier rather than merely adding small noise.

The system also carries relatively short messages compared with ordinary communication tools. This is intentional: increasing the payload too aggressively can reduce reliability or create detectable patterns. The method is therefore better suited to short text, identifiers, verification codes, and compact metadata than to large files.

\subsection{Responsible Use}
Steganography can support privacy, ownership tracking, and secure research communication, but it can also be misused. Practical deployments should follow applicable laws, organizational policies, and consent requirements. Systems should include access controls and should not be presented as a replacement for encryption. Encryption protects message contents, while steganography mainly attempts to hide the presence of the message; using both provides a stronger design.

\subsection{Future Improvements}
Future work can evaluate larger and more varied images, additional diffusion models, and a greater number of test messages. It would also be useful to test common real-world changes such as JPEG compression, resizing, screenshots, color adjustment, and social-media upload pipelines. Adaptive protection could automatically select a stronger error-correction level when the expected channel is unreliable.

Further research may also combine the method with modern encryption and key-management systems, reduce the time needed for repeated recovery, and develop clearer capacity guidelines. These improvements would help determine how well the approach moves from a controlled experiment to practical communication environments.

\section{Conclusion}
In this paper, we introduced an exact, distribution-preserving, and error-resilient generative diffusion steganography pipeline. By pairing an iterative fixed-point DDIM inversion solver with Distribution-Preserving Arithmetic Coding (DPAC) and rate-adaptive systematic error correction, our system eliminates trajectory drift, shows no statistically significant deviation from Gaussian noise in our tests, and provides autonomous error recovery. Rigorous benchmarks across 20 trials demonstrated a flawless 0.000000\% Bit Error Rate, 100\% extraction success, high visual fidelity ($\mathrm{PSNR} \ge 45.59$\,dB), and no detectable statistical deviation from the expected noise distribution ($p=0.4191$).
